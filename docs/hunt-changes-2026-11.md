# 2026 年 11 月 14–15 日自动狩猎变更

本文记录从 `85b581e` 到 `5b8fc67` 的改动。当前实战配置针对**地铁一号线第 4 地区的幽灵**。默认模式会清当前平台、追击同层远怪，再按地图标注换层。组队时可以锁定自己负责的平台。

## 运行模式

| 场景 | 启动命令 | 实际行为 |
| --- | --- | --- |
| 单人清图 | `.\run.bat` | 先清当前平台。走向梯子时遇到可打的同层怪会回到战斗，已经起跳则优先完成攀爬。 |
| 组队分区 | `.\run.bat --single-platform` | 锁定启动后首次识别的平台。只打该平台射程内的怪，掉到别层后暂停攻击，回到原台恢复。 |
| 原地挂机 | `.\run.bat --stationary` | 使用原有的局部检测和原地攻击循环。 |
| 核对识别和路线 | `.\run.bat --observe` | 只读预览角色脚底、平台、怪物归属和候选连接。 |

当前配置启动时进入 `hunt`。游戏窗口在前台时才接收脚本输入。`F1` 开关键盘控制，`F11` 切换识别与狩猎。自动拾取已关闭，补血补蓝交给游戏内宠物。[运行配置](../config/config_custom.yaml)

## 从发现幽灵到出招

1. **定位角色。** Windows 按游戏窗口句柄采集客户区，等比缩放到 1280 像素宽。优先用绿色称号定位，局部遮挡时尝试匹配露出的部分。称号识别失败时，地图对齐且小地图黄点唯一才使用黄点估算脚底位置。
2. **决定是否追怪。** 先扫角色附近。附近有可打的同层幽灵就直接攻击，否则扩大到整个可见玩法区。当前平台还有远怪时先走近；刚清过的平台连续扫空两次才考虑换层。日志里的 `visible` 是本次扫描看到的数量，`in_range` 是这一帧筛选出的攻击目标数。
3. **按状态发键。** 状态机每帧决定移动、朝向和动作。连续两帧都要向左走时，键盘保持左键；改向右走时，先松左再按右。当前跳攻按技能节奏逐次点按，起跳期间目标消失会取消后续攻击。

| 当前攻击参数 | 值 |
| --- | --- |
| 技能判定框 | **400 × 200 像素**，以角色定位点为中心，左右各 200、上下各 100，按怪物框中心判定 |
| 单攻与群攻 | 都用 `S`，射程内达到 3 个目标时选择群攻 |
| 跳攻节奏 | 点 `C` 约 80 ms，再点 `S` 约 60 ms，两次攻击起跳至少间隔 650 ms |
| 高台居中 | 默认和组队守台模式下，偏离平台中心超过 20 像素时先按住朝内的方向键，再跳攻，出招后松开。怪在外侧时先向内起跳，空中转身出招。中心附近原地攻击，地面和铁轨沿用原走位。 |

早期版本曾在目标进入射程时持续按住攻击键。当前配置启用了 `bot.jump_attack`，所以连续看到目标时会重复执行上述 `C`、`S` 序列。[状态机](../src/engine/CharacterFSM.py) · [按键执行](../src/input/KeyBoardController.py)

## 换层与爬梯保护

地图标注覆盖两端出口之间的平台、梯子和下跳点。镜头滚动时用固定地标将脚底位置换算为地图坐标。上层还有怪时，导航可以经中间平台分段攀爬；下层路线则在标注点按住 `↓`、点 `C`、再松开 `↓`。[平台与连接标注](../maps/subway_line1_area4/platforms.yaml)

所有梯子使用同一套起跳规则，包括通往 `upper_right` 的入口。导航根据画面时间和接近速度估算起跳位置。预计距梯口 44 像素以内可以斜跳，正下方可以直跳。斜跳时先按住朝梯子的方向键和 `↑`，约 7 ms 后按 `C`，约 30 ms 后松 `C`。到达梯子中心时松横向键，横向持键上限为 200 ms。

**1200 ms 是起跳后保护 `↑` 的时长。** 保护期间攻击、走位和下跳都要等。到时仍在攀爬就继续按住 `↑`。失焦、手动暂停或显式停止会释放按键。角色已经挂在梯子中段时，导航可根据连续位置观测恢复按上攀爬。确认尝试失败后，该入口暂避 30 秒，再规划可用路线。[爬梯导航](../src/engine/LadderNavigator.py)

## 实战记录与验证

11 月 15 日，两次从 `middle_east` 前往 `upper_right` 的日志都指向地图横坐标 1644 的梯子。下表中的位置按日志里的脚底横坐标减去镜头偏移计算。

| 起跳时间 | 起跳 → 重试的地图横坐标 | 脚本记录的 ↑ 持续时间 | 结果 |
| --- | --- | --- | --- |
| 02:40:59 | 1684 → 1590 | 1084 ms | 从梯子右侧跳到左侧，仍在原平台，进入重试 |
| 02:51:26 | 1675 → 1575 | 1251 ms | 越过梯口，重试时未识别到落脚平台 |

第二次记录说明延长保护后仍会出现越过梯口的情况。两次都是导航先进入 `LADDER_RETRY`，键盘随后记录松开 `↑`。日志能确认脚本的发键顺序；游戏在哪一帧判定抓梯，以及居中跳攻是否影响这两次起跳，仍待实战验证。

复查一次失败时，在同一份运行日志中依次查找 `WALK_TO_LADDER -> CLIMB`、`Jump sent with Up held`、`CLIMB ->` 和 `Up released after`，用状态变化、落点和松键原因核对。当前版本的 79 项自动测试覆盖了同帧输入切换、攻击边界、目标消失、斜跳及 1200 ms 保护边界。可在仓库根目录运行：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s test -p 'test_*.py'
```
