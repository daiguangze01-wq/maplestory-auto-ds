# 游戏脚本「反检测」操作调研

> 口径：本文是**检测面（detection landscape）研究**，不是绕过手册。
> 调研时间：2026-10；主要参照：冒险岛系列（韩服 / 国服怀旧服 / 私服 / MapleStory Universe）+ MMORPG 通用做法。
>
> **一句话结论**：脚本作者做的"额外操作"能分成七类，但按"真正延长账号寿命"的贡献排序，只有两类有效——**降低账号的在线与产出显著性**、**保证验证弹窗出现时有人类应答**。其余（改进程名、随机 sleep、模拟鼠标轨迹、换硬件宏）多数只对弱检测有效，对服务端统计、人口级聚类、举报体系基本无效；其中一部分（多开、虚拟硬件、VPN、远程控制、篡改 PC 信息）在官方规则里**本身就是违规证据**。

---

## 0. 摘要

| # | 结论 | 证据强度 |
|---|---|---|
| 1 | 封号的主力不是"客户端检测"，而是**服务端记录 + 验证弹窗 + 举报/人工** | 官方规则、封号公告、学术论文 |
| 2 | 随机化只洗掉"一阶特征"（均值、一眼可见的规律），洗不掉分布形状、熵、跨会话周期 | 检测方公开方法 |
| 3 | 真正有杀伤力的是**人口级聚类**：不是"你像不像人"，而是"你和一群账号像不像" | 2025 年论文（成长曲线无监督聚类） |
| 4 | 官方明确**回溯 90 天**，封号滞后于违规时点 → 你永远拿不到有效反馈 | Nexon 官方页面 |
| 5 | 最有效的反检测手段恰好是"少赚"：限时、作息、错峰、慢速 | 官方明写的检测依据 |
| 6 | 一部分"伪装"行为被规则单独列为违规，做了等于自证 | Nexon 11 条不建议行为 |

## 1. 检测方到底能看见什么（七层）

| 层 | 典型信号 | 谁在看 | 脚本能不能"洗掉" |
|---|---|---|---|
| **L0 客户端环境** | 进程/模块/窗口标题、DLL 注入、调试器、虚拟机、抓屏与输入 API、已知工具名单 | 内核/用户态反作弊（Vanguard、BattlEye、EAC、nProtect GameGuard、BlackCipher/NGS…） | 外部"截屏 + 发按键"形态天然少痕迹；但工具链不干净会被名单命中 |
| **L1 输入来源** | `LLKHF_INJECTED` / `LLMHF_INJECTED`、Raw Input 对不上硬件事件、HID 设备枚举、按键时序 | 反作弊 + 驱动 | 软件注入容易洗；硬件宏洗掉"注入"但暴露设备 |
| **L2 单账号时序** | 按键间隔分布（人类重尾 vs 脚本固定）、方差/熵/自相关、循环周期、反应时间 | 服务端日志 + ML | 一阶可洗，二阶很难 |
| **L3 账号/设备/IP** | 多开、同 IP/同 HWID 多 ID、代练与共享账号、地理位置跳变 | 运营后台 | 难，且伪装本身违规 |
| **L4 服务端游戏记录** | 经验/金币/掉落曲线、单位时间收益、可通关性（装备 vs boss）、90 天回溯 | 数据分析 + 运营 | 只能靠"少赚"来洗 |
| **L5 人口级聚类** | 成长曲线/行为序列的相似群体（无监督对比学习 + 聚类 + LLM 复核） | 平台方 | 单账号几乎无法对抗 |
| **L6 验证弹窗** | 测谎仪/CAPTCHA/小游戏、通过率与耗时、累计失败 | 游戏内系统 | 能识别、能报警；"自动解"成本持续上升 |
| **L7 人工** | GM 巡查、玩家举报（冒险岛的举报是**道具化**且有奖励）、封号公告 | 人 | 只能靠"不显眼" |

> 关键认知：L2 以上是"概率与统计"，L6/L7 是"人类注意力"。客户端伪装（L0/L1）只影响最前面一层，而绝大多数封号发生在后面几层。

### 1.1 输入链路的四条路径与三档可见性

这是客户端层最硬的一条证据。微软自己的 UI 自动化命令行文档把差异写得最直白：默认的 `post-message` 传输"**无法触发通过 WH_KEYBOARD_LL 注册的全局热键**"，用 `GetAsyncKeyState` 读键状态的应用"**可能观察不到按住的修饰键**"；而 `send-input` "**产生完全真实的输入**（修饰键对 GetAsyncKeyState 可见，并触发低层钩子）"。([Microsoft WinAppCli UI automation 文档](https://learn.microsoft.com/en-us/windows/apps/dev-tools/winapp-cli/ui-automation))

| 路径 | 进系统输入流 | 低层钩子 / 注入标志 | GetAsyncKeyState | Raw Input 设备归因 |
|---|---|---|---|---|
| `SendInput` | 是 | 可见，带 `LLKHF_INJECTED` / `LLMHF_INJECTED` | 可见 | 通常无（官方未承诺，按未确证处理） |
| `keybd_event` | 是（旧接口） | 可见，通常同样被标记 | 可见 | 无 |
| `PostMessage` | 否，只进目标线程消息队列 | 不可见 | 不可见 | 无 |
| `SendMessage` | 否，直接调用窗口过程 | 不可见 | 不可见 | 无 |

标志位定义在结构体里：`KBDLLHOOKSTRUCT.flags` 的 `LLKHF_INJECTED`（是否被注入）、`LLKHF_LOWER_IL_INJECTED`（是否来自更低完整性级别）；`MSLLHOOKSTRUCT.flags` 的 `LLMHF_INJECTED`。([KBDLLHOOKSTRUCT](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-kbdllhookstruct)、[MSLLHOOKSTRUCT](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-msllhookstruct))

**Raw Input 是用户态最直接的"输入 → 设备"归因通道**：按 TLC（UsagePage 0x01 / UsageID 0x06 即键盘）注册后可拿设备句柄，能区分"同一类型的两只鼠标"，并处理 1000Hz 级高频事件。([About Raw Input](https://learn.microsoft.com/en-us/windows/win32/inputdev/about-raw-input)) 一个从未被物理使用、却持续产生按键的 HID 端点，本身就是异常。

### 1.2 主流客户端反作弊方案速查

| 方案 | 客户端做什么 | 内核态 | 证据强度 |
|---|---|---|---|
| nProtect GameGuard（INCA） | 反加速/宏/挂钩/调试；EXE/DLL 加密、CRC、模式库，客户端-服务端双重认证 | 官方未写，社区长期称带驱动 | 功能【确证】/内核【未确证】([官方页](https://nprotect.com/products/nprotect/gameguard)) |
| XIGNCODE3（Wellbia） | OS 层检测、**宏输入设备检测**、外部连接检测、模式与白名单、禁多开、资源防改 | 未公开 | 【确证】([官方页](https://wellbia.com/?module=Html&action=SiteComp&sSubNo=1)) |
| BattlEye | 主动拦截 + 内存/磁盘扫描 | 是（论文称 Windows 内核级） | 【确证】([FAQ](https://www.ubisoft.com/en-gb/game/rainbow-six/siege/news-updates/2999gdyIXLbeiZP78R7545/battleye-faq)、[CheckMATE 2025](https://hal.science/hal-05482209)) |
| EAC（Epic） | 官方称"分层""预防优先" | 官方未明说 | 【部分确证】([官方页](https://www.easy.ac/services)) |
| Vanguard（Riot） | 内核驱动、开机启动、可阻止文件加载 | 是 | 【确证】([官方页](https://support.riotgames.com/en-us/riot/performance/what-is-vanguard)) |
| BlackCipher / NGS（Nexon） | 公开技术资料极少 | 社区称内核 + 多进程 | 【未确证】 |

一个值得注意的厂商事实：**XIGNCODE3 官方功能列表里明确写了"检测并阻断各类宏输入设备"**。而 KMBox 这类硬件盒子的官方自述是"支持自定义 USB 所有描述符""回报率 100–8000Hz 可调""支持监控物理键鼠、屏蔽物理键鼠"([产品页](https://www.kmbox.top/productIntro.html))——这说明**单看 VID/PID 不足以识别伪装 HID**，但"设备归因是否自洽"仍是硬约束。

## 2. 脚本作者常见的七类"额外操作"

### A. 时序拟人（最普遍，收益最小）

**做法**：随机 sleep、抖动、正态/对数正态采样、按键按压时长变化、鼠标贝塞尔曲线、微停顿、疲劳曲线、动作冷却。

**行业实证**：开源 OSRS 机器人框架 microbot 的 `Rs2Antiban` 把这套东西直接做成了 API——micro-break、mouse fatigue、random interval、non-linear interval、behavioral variability、按"活动类型 + 强度"分级、鼠标移出屏幕模拟离开。([Rs2Antiban 文档](https://github.com/chsami/microbot/blob/a2114401bbbc35e9762db9e8aa666d70ffcd24d8/docs/api/Rs2Antiban.md))

**打掉**：固定周期的均值、一眼可见的规律。
**打不掉**：分布形状、熵、自相关、跨会话周期，以及产出曲线。

**一条关键的否证**：QUACK 的实验显示，速度/规律性启发式确实能被"放慢 + 随机化"绕过，但**在不读按键内容、不做用户画像时，纯时序模型仍能区分人机，且跨生成器可迁移**；更复杂的合成并不单调提升逃逸率——判别力主要取决于检测方训练时见过多少种结构不同的生成方式。换句话说，随机化不是"变得像人"，只是"变成另一个可被学习的分布"。

### B. 输入链路升级（软件 → 驱动 → 硬件 → 双机）

**层级**：`PostMessage/SendMessage`（很多游戏已不认）→ `SendInput`/`keybd_event`（带 INJECTED 标志，[微软文档确认可归因到进程](https://learn.microsoft.com/en-nz/answers/questions/2122732/how-do-i-know-which-process-trigger-the-injected-k)）→ 驱动级 → USB HID 硬件（Arduino / 树莓派 / KMBox，见 [KMBox 手册](https://topwww.kmbox.top/wiki_doc/kmboxB-en/site/tools/kmboxB%E7%89%88%E7%94%A8%E6%88%B7%E6%89%8B%E5%86%8C.pdf)) → 双机/串流。

**打掉**：注入标志、前台焦点要求、Raw Input 对不上。
**新增暴露面**：HID 设备枚举（VID/PID/描述符/报告速率）、驱动加载、双机 = 远程控制。
**重要提示**：越往底层走，越接近"外挂"的定义。腾讯《穿越火线》的[官方禁用软硬件清单](https://cf.qq.com/webplat/info/news_version3/125/860/861/m640/202409/959578.shtml)直接点名 DMA、KMBox、树莓派/Arduino 等开发板、硬件宏、按键精灵/AutoHotkey/Python 脚本、虚拟机、远程控制与抓帧工具。

### C. 行为多样化

**做法**：路径随机/路径点抖动、技能循环变体、故意漏怪漏捡、无意义走动、表情/聊天/站街、偶尔回城、看拍卖。

**打掉**：重复度、熵、路径效率这些"看录像就能发现"的特征。
**打不掉**：单位时间收益、在线时长、成长曲线。

### D. 会话与作息（性价比最高）

**做法**：每日时长上限、分段休息、模拟人类作息（夜间少玩/不玩）、错峰、多账号轮换、工作日/周末不同节奏。

**打掉**：24/7 在线、凌晨高产、连续十几小时同一动作——这些是运营最先看的。
**代价**：直接等于收益下降。这是它有效的原因，也是脚本作者最不愿意做的部分。

### E. 环境伪装

**做法**：改进程名/窗口标题、隐藏窗口、虚拟机/沙箱、伪装设备指纹、反截屏。

**打掉**：进程/窗口名单、抓屏类检测。
**反作用**：Nexon 把"同时运行异常程序 / 篡改 PC 与通信信息 / 虚拟硬件 / 多开 / 远程程序 / VPN"直接列为"可能被视为规避检测"的行为（见 §3.1）。这一层做得越多，越像在作弊。

### F. 验证弹窗应对

**层级**：CV 识别弹窗 → **告警给人（半自动）** → 自动解（OCR/CV/LLM）。

**现状**：冒险岛的测谎已经演化成小游戏 + 生成式 AI 题（见 §3.2），自动解的门槛在快速抬高；答错/超时的代价是阶梯式惩罚（§3.3）。
**判断**：告警给人是唯一可持续的方向；自动解是军备竞赛里最先失效的一环。

### G. 经济与节奏控制

**做法**：控制单位时间经验/金币、分散出货、慢速练级、避免"低战力高产出"。

**打掉**：经济离群、可通关性异常。
**打不掉**：聚类层面的相似性。

### 汇总表

| 手段 | 主要打掉 | 基本打不掉 | 副作用 / 新增风险 |
|---|---|---|---|
| A 时序拟人 | 固定周期观感 | 分布、熵、产出曲线 | 几乎没有；**收益也几乎没有** |
| B 输入升级 | 注入标志、前台要求 | 设备枚举、服务端记录 | 硬件指纹、厂商点名封禁、成本高 |
| C 行为多样化 | 重复度、路径效率 | 收益曲线、在线时长 | 开发成本高，收益有限 |
| D 会话作息 | 24/7、凌晨高产 | 单次行为特征 | **收益线性下降**（所以有效） |
| E 环境伪装 | 进程/窗口名单 | 服务端一切 | **本身列为违规**，越做越可疑 |
| F 弹窗应对 | CAPTCHA | 通过率统计、人工巡查 | 自动解的成本持续上升 |
| G 经济控制 | 经济离群 | 聚类相似性 | 收益下降 |

## 3. 冒险岛：一个持续 20 年的样本

### 3.1 官方规则里明写的检测依据

Nexon 韩服「권장하지 않는 플레이 방식 안내」列出 11 类不建议行为，与脚本相关的核心几条：

1. 通过 ID 共享在他人账号上游戏；
2. 使用远程程序或 VPN 连接/游戏；
3. 多开（含利用 OS 自带功能的多开）；
4. 用监控/控制多台 PC 的程序或设备同时玩多个 ID；
5. **IP/MAC 伪造、虚拟硬件等伪装程序**；
6. **带输入重复功能（宏）的键盘、鼠标、摇杆、手柄等硬/软件**——"使用本身不限制，但若因此被检测到超出正常范围的游戏记录，可能被处罚"；
7. 私服等非官方未授权程序；
9. **反复通不过游戏内安全服务（测谎仪、Violeta 等）**；
10. **在同一系统信息（IP、PC）上用多个 ID 收集游戏内货币/道具牟利**——"从被检测到异常记录的系统信息登录时，视为同一人"；
11. 其他与大多数玩家不同的游戏方式反复出现。

并且明确：

- 处罚**不只看封号前记录，会回溯最近 90 天的游戏记录**，所以封号时点与违规时点可能不同；
- 多条违规按最重项处罚；
- 申诉时需要玩家说明"重复相同按键长时间游戏"时的技能循环与按键内容。

来源：[Nexon 韩服官方页面](https://gi.maplestory.nexon.com/Guide/GameInformation/InfoForNewbie/BadPlayStyleInfo)；繁中对照版见 [MapleStory N 文档](https://aliceric27s-organization.gitbook.io/msu-tw/feng-zhi-gu-101/xin-shou-zhi-nan/kai-shi-you-xi/bu-jian-yi-de-you-xi-xing-wei.md)。

MapleStory Universe 的 Director's Note 更直接：已上线**多层检测系统，分析 level / equipment / clear time / combat patterns**；日均处罚 10,000+ 账号；另有"每天处理数百到数千例"的人工巡查；并对"装备与通关可行性明显矛盾"的异常 BOSS 通关做专项分析。([Director's Note](https://docs.maplestoryn.io/archives/updates/developer-notes/directors-note-response-to-abnormal-boss-clears-and-bot-abuse.md))

### 3.2 测谎系统时间线（2005 → 2025）

| 时间 | 形态 |
|---|---|
| 2005-04-25 测试服 / 05-03 韩服正式 | 玩家可购买「测谎机」对他人使用，弹 CAPTCHA 要求输入随机词；未通过 → 传送到附近村庄 + 罚 7000 枫币，举报者得 7000 |
| 2005-11（国服报道） | 国服引入同款道具（[17173 2005 报道](https://news.17173.com/content/2005-10-29/20051029124035059.shtml)） |
| 2018-03-29 | 「화장한 비올레타를 찾아라」：4 个 Violetta 换位，追 4 次 |
| 2018-12-13 | 「진실의 방」（真実之屋 / 监狱）上线 |
| 2020 前后 | 「点击测谎」：60 秒内点 5 次，窗口每次随机移动，点错清零 |
| 2022-10-27 | 「올바른 문장을 찾아라」：5 句里找 1 句通顺的，4 次机会答对 ≥3 |
| 2024-03-21 / 05-23 / 06-20 | 采集触发 Violetta；「투명 도형 찾기」拖鼠标跟形；打怪也触发 |
| 2024-07-18 | 语音测谎（无障碍替代方案） |
| 2025-08 | **生成式 AI 测谎**（看图答题） |

道具本身的设定：商店购买（最初 20 万 meso，后降为 1 万），**只能对"战斗中或采集农场里"的角色使用**，同一玩家有冷却（约 10 分钟）；服务器可自动施放，GM 另有对应技能；玩家也能买来对他人施放，因此常被用于抢图骚扰。([mapleclassic.wiki](https://mapleclassic.wiki/wiki/Lie_Detector_Test))

触发条件：打怪/采集/战斗后一段时间、GM 的群体技能、武陵道场换层、迷你副本、**同一 IP 当日第 6 个账号登录**、以及玩家道具。
（以上细节多来自社区百科，**官方从未公开触发规则**；玩家用来解释的"찍계"——凌晨、超长在线、重复刷怪、符文失败、频繁换机会提高概率——属于【传言】，不可当事实引用。）

误判并不为零：GMS 论坛有玩家称 10 天内被弹十余次、且多发生在固定刷怪图，官方论坛因此出现过"测谎太敏感"的反馈帖。([GMS 论坛](https://forums.maplestory.nexon.net/discussion/35873/lie-detectors-are-too-sensitive))

### 3.3 惩罚阶梯

- **真実之屋**按累计进入次数计停留时间：1 分钟 / 3 分钟 / 5 分钟 / 10 分钟 / 1 小时 / 3 小时 / 6 小时 / 12 小时 / 24 小时；干净游戏一周减 1 次。
- **红账号（Red Account）**：禁交易、拍卖、邮寄、메소마켓；解除需缴纳 ≥1 亿 meso。
- 可疑度越高，测谎出现越频繁、难度越高（按日调整、随用户熟练度上升）。
- 社区把被标记的号叫「찍계」：点击测谎出现即视为风险信号，难度继续上升则说明"被盯上了"。

### 3.4 私服也照抄

韩国私服 MaplePlanet 在 2026-02-25 上线测谎系统：杂货店买道具 → 输入可疑角色名 → 对方必须通过小游戏；失败（次数超限/超时）→ 传送回村庄。([公告](https://mapleplanet.io/news/notices/336))

### 3.5 国服怀旧服

- 测谎仪是正式道具（[道具库](https://mxd.dvg.cn/item_info.php?id=2190000)），运营有固定的「违规行为处理公告」栏目（例：[10 月 25 日处理公告](https://mxdc.web.sdo.com/web2/newsContent.html?id=394658&CategoryID=8469)）。

### 3.6 学术侧：从"像不像人"到"像不像一群人"

这一节是整篇调研里最重要的部分——它解释了为什么"拟人化"的上限很低。

- **基石论文：自相似性（NDSS 2016）**。Lee 等提出用"单个玩家在一段时间内重复活动的频率"来度量 bot，在《天堂》《Aion》《剑灵》三款真实 MMORPG 数据上验证；关键点是该特征**与具体游戏内容解耦、可跨游戏复用**。也就是说：检测的不是"你按了什么键"，而是"你的活动自我重复得有多像机器"。[You are a Game Bot! (NDSS 2016)](https://pure.skku.edu/en/publications/you-are-a-game-bot-uncovering-game-bots-in-mmorpgs-via-self-simil/)
- **纯时序模型仍能区分人机（QUACK）**。只用按键 hold/flight 时间训练轻量分类器：速度与规律性启发式确实能靠"放慢、随机化"绕过，但在不读按键内容、不做用户画像时，纯时序模型依然能区分，而且**跨生成器可迁移**；更复杂的合成并不单调提升逃逸率，判别力主要取决于训练时见过多少种结构不同的生成方式。[arXiv 2604.15845](https://arxiv.org/abs/2604.15845)
- **经济/进度的 LSTM**。Aion 数据上用角色财务状态（现金、物品数、仓库、邮寄资产）的时间序列做二分类，平均准确率 0.947、F1 0.950；作者明确接受精确率低于召回率，因为产出的是**可疑名单**而不是直接封号。工业版进一步把"现金时序 + 相对市价的异常交易"做集成，标签直接用"是否被停权"。([arXiv 1908.03748](https://arxiv.org/abs/1908.03748)、[JKDI 2024](https://doi.org/10.7465/jkdi.2024.35.4.461))
- **只靠交易日志也能判**。某手游三个月拍卖行日志即识别出金币工作室的"单一角色"结构，用于绕过 RMT 限制的洗钱路径。[IEEE ToG 2021](https://doi.org/10.1109/TG.2021.3094054)
- **无监督 + LLM 复核**：找出"升级模式相似"的角色群，LLM 做二次复核，配成长曲线可视化，兼顾可解释性（封号需要解释得清）。[Human-AI Collaborative Bot Detection in MMORPGs (arXiv 2508.20578, 2025)](https://arxiv.org/abs/2508.20578)
- **方法谱系**：RF/XGBoost 仍是工业基线，问题常是特征选错而非模型不够强；SHAP 已被用来反向诊断"AI 检测为何失效"，当作上线前的可解释性验收（[KSII 2025](https://doi.org/10.3837/tiis.2025.02.010)）。LSTM/集成吃"必要条件"；Transformer 已进入竞技类游戏的作弊检测（[arXiv 2508.06348](https://arxiv.org/abs/2508.06348)），但其输入是竞技对局的操作/瞄准序列，**不能直接照搬 MMORPG**；DBSCAN/交易网络用于生成无监督候选池，人工复核后才封。
- 其他：服务端 ML 作弊检测 [IEEE 11711495](https://ieeexplore.ieee.org/document/11711495)；经典综述 [Mitterhofer et al., IEEE S&P 2009](https://dl.acm.org/doi/10.1109/MSP.2009.78)；输入行为区分真人/不可信程序 [NATO STO](https://www.sto.nato.int/publications/STO%20Meeting%20Proceedings/RTO-MP-IST-041/MP-IST-041-21.pdf)。

> **口径提醒**：0.947 这类效果数字建立在厂商私有数据 + 人工标签上，标签定义、时间窗、样本比例都不同，**不能横向排名**；暴雪（WoW）不公开检测方法，只有处罚公告与诉讼材料可依；MapleStory 的触发条件只能引用社区推断。

## 4. 为什么"拟人化"整体是收益递减

1. **你优化均值，对方看分布。** 随机 sleep 只改了均值和一眼观感；检测方算的是方差、自相关、熵、周期长度——这些恰恰被"加噪声"保留了下来。
2. **随机化改的是边际分布，不改联合结构。** 自相似性、序列 n-gram、条件延迟分布对"你按了什么键"不敏感，加噪只会让序列变成"另一个分布"，而不是更像人类（NDSS 2016）。
3. **人类的一致性本身就是特征。** 按键动力学能做身份识别，正因为同一个人的 hold/flight 时间有稳定风格；噪声调大，会同时破坏"像人"和"像这个玩家"（QUACK）。所以"完全随机"反而不像人。
4. **你优化单个，对方看群体。** 检测是排序不是阈值：只要你和另外一批同类账号同分布，聚类就出来了（§3.6）。
5. **经济层是绕不开的必要条件。** 操作可以伪装，财富曲线与异常交易关系不行；而运营还会继续升维——从"能不能自动解题"到"懂不懂语义、跟不跟得上视觉追踪"，再到红账号**直接切断交易**，解题成功也不再等于收益。
6. **反馈被延迟 90 天。** 你无法验证"拟人化"有没有用——唯一的反馈是封号，而封号追溯的是 90 天前的记录。这是最要命的信息不对称。
7. **成本不对称。** 举报一次按两下键，玩家还有奖励；你要为"不被举报"持续加码。
8. **最有效的检测最简单。** 在线时长、单位时间收益、验证通过率、举报次数、可通关性——都不需要机器学习。
9. **部分"反检测"本身违规。** 多开、虚拟硬件、VPN、远程控制、篡改 PC 信息在官方规则里是独立违规项，做了等于自证。

**人类化的真正上限**：不在"像人"，而在三件事无法同时满足——**足够高的收益/时间比、与人类总体分布一致、长期不暴露重复结构**。要提高产出，就得拉高占空比、压低方差、固定路线与时段；而这三项恰好都是可测的统计量。人类的低效、停顿、失误与作息波动，是检测器最好的先验。

## 5. 对着这个仓库看：现有技术栈的风险评分

> 这一节只做**风险排序**，不是实施清单。

| 风险 | 现状 | 说明 |
|---|---|---|
| **高：验证弹窗无人应答** | README 列了「测谎报警」，但 `src/` 下没有任何相关代码 | 在国服怀旧服，弹窗出现却无人应答 = 阶梯进监狱 → 红账号。这是当前最大的缺口 |
| **高：在线与产出显著性** | 无每日时长/作息/休息模型 | 恒速产出 + 长时间在线，是最容易被统计出来的组合 |
| **中高：时序周期性** | 主循环 10–15 FPS，`sleep(1/fps)` 固定节拍；全仓库只有 `search_random_jump_chance: 0.03` 一个随机点 | 固定节拍是最明显的单账号统计特征 |
| **中：行为单一** | 同地图、同路线、同技能循环；无社交、无休息、不死亡、不迷路 | 录像层面也容易辨认 |
| **中：设备/账号关联** | 多开、同机同 IP | 官方明写"同一系统信息视为同一人" |
| **低（私服）/ 高（官服）：输入注入** | `pydirectinput` → `SendInput`，带注入标志，且要求前台 | 对无内核反作弊的 079 私服基本无所谓；对官方服是明文痕迹 |
| **低：窗口抓取** | `mss` + `FindWindow(标题)` + `GetWindowRect` | 窗口标题/前台状态外部可观察；改标题程序直接失联 |

另外：README 里"已经被封了 3 个号"本身就是最直接的实验数据——说明目前这套策略在目标服务器上的存活周期已经暴露。

## 6. 常见误解

| 说法 | 实际 |
|---|---|
| "随机 sleep 就查不出来" | 只改均值；方差/熵/周期仍在，且要和人群比 |
| "改进程名/隐藏窗口就安全" | 服务端不看进程，看记录；反而踩"篡改 / 多开"违规 |
| "硬件宏不可检测" | 设备枚举 + 厂商点名封禁；且只解决最前面一层 |
| "号多就分散风险" | 同 IP/设备/支付关联，一起封；官方明写"同一系统信息视为同一人" |
| "过了测谎就没事" | 通过率本身是可疑度输入；失败累计有阶梯惩罚；红账号不看单次 |
| "私服没人管" | 私服 GM 权限更大（封 IP/MAC 更随意），且可能和支付渠道联动 |
| "模拟人类鼠标轨迹就够了" | 人类差异主要不在轨迹形状，而在"为什么动、什么时候动" |

## 7. 边界与风险

- **ToS 层面**：所有主流 MMO 都禁止自动化；封号、设备/IP 封禁、红账号、连带封关联账号都是既有做法，官方规则里写得很清楚。
- **法律层面**：韩国、中国都有围绕"外挂 / 代练 / 破坏计算机信息系统"的判例；私服本身另有法律风险。
- **本文不提供**：具体反作弊绕过、注入/驱动级隐藏、设备指纹伪造、CAPTCHA 自动求解的实现。原因不是姿态，而是：(a) 这些是违规且法律风险最高的一层；(b) 在 2026 年的检测栈里，它们恰恰是最容易失效、最容易暴露的一层。
- **真正可持续的两种做法**：把它当"半自动辅助 + 人类随时接管"（弹窗必须有人应），或者接受"这是概率游戏，封号是预期成本"。
